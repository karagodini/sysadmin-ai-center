# Железные правила разработки (Strict Workflow)

1. **НИКАКИХ правок «наживую» в продакшн-коде** (в рабочей ветке `main` на сервере).
2. **Порядок работы для ЛЮБОЙ задачи:**
   - Создать новую ветку (`git checkout -b feature/...`).
   - Написать код и сделать коммит.
   - Сделать `git push` этой ветки на GitHub **ДО** деплоя на продакшн.
   - Проверить работоспособность (тесты / синтаксис / запуск).
   - Только после успешной проверки и подтверждения делать Merge в `main` и обновлять продакшн.
3. **Гит — первичнее сервера.** Код сначала должен оказаться в системе контроля версий (и на GitHub), и только потом становиться частью работающей панели.

## Железное правило разработки
При любых изменениях (редактировании/добавлении файлов/папок):
1. Всегда создается отдельная ветка.
2. Все правки и новые файлы делаются в этой ветке.
3. Проводятся тесты и проверки работоспособности.
4. После успешных тестов ветка вливается (`merge`) в `main`, пушится на GitHub и применяется на продакшн-сервере.
5. Запрещено вносить изменения напрямую в `main` или на продакшене без прохождения через ветку и тесты.
